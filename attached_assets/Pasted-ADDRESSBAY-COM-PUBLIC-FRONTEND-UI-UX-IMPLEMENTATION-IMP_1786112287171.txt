ADDRESSBAY.COM — PUBLIC FRONTEND UI/UX IMPLEMENTATION

IMPORTANT SCOPE RULE

The existing AddressBay Phase 1–32 implementation specification already contains the required Admin UI/UX and Admin Dashboard work.

DO NOT redesign, replace, duplicate, or remove the Admin UI/UX requirements from the existing Phase 1–32 specification.

This task is specifically for the PUBLIC-FACING FRONTEND UI/UX of AddressBay.com.

The objective is to transform the public website into a world-class global business-data discovery platform while remaining fully compatible with the existing and planned Phase 1–32 backend architecture.

⸻

1. PUBLIC WEBSITE ONLY

Redesign and improve only public-facing pages and components.

The frontend must support:

* India
* Australia
* United Kingdom
* Singapore
* USA
* future countries

Do not hardcode the frontend around India.

The architecture must allow additional countries without redesigning the UI.

32. DO NOT DUPLICATE ADMIN WORK

IMPORTANT:

Do not redesign or replace the Admin UI/UX already specified in the existing AddressBay Phase 1–32 implementation plan.

Do not modify Admin Dashboard layouts unless required for compatibility with the backend changes.

Do not create a second Admin design system.

This task is specifically the PUBLIC FRONTEND UI/UX layer.

⸻

33. IMPLEMENTATION RULE

Before changing code:

1. Inspect the current frontend.
2. Inspect the existing Phase 1–32 implementation.
3. Reuse existing APIs and components where appropriate.
4. Do not break existing functionality.
5. Do not change database architecture as part of this task.
6. Do not modify backend behavior unless required to expose already-planned frontend data.
7. Keep the frontend compatible with future countries.

⸻

34. FINAL QUALITY STANDARD

The final AddressBay public website should feel like:

A global business intelligence and company discovery platform — not a simple company directory.

Prioritize:

Usability

Performance

Trust

Data readability

SEO

Mobile experience

Scalability

Professional visual design

Do not sacrifice functionality for visual effects.

Do not sacrifice performance for animation.

Do not sacrifice accessibility for aesthetics.

Do not create artificial pages or links solely for SEO.

Build the public frontend as a long-term global product.
